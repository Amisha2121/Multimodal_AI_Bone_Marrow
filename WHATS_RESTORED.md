## 📊 Data Flow (How It All Works)

```
User uploads images
    ↓
Flask receives files → saves to uploads/
    ↓
Calls analyze_new_case()
    ↓
Pipeline processes:
    • Detects cells
    • Classifies cells
    • Generates 3 image types:
        - Raw candidates
        - Filtered detection
        - Contact sheet
    • Crops individual cells
    ↓
Results stored in memory (analyses dict)
    ↓
Frontend displays:
    • Metrics dashboard
    • Three image views
    • Cell distribution table
    ↓
User can then:
    • Chat (uses RAG + LLM)
    • Generate report (uses RAG for each section)
    • Browse cells (filtered by type)
    • Switch to past analyses (history)
```

## 🔧 Technical Implementation

### Frontend (React)
- **File**: `app/static/index.html`
- **Technology**: React 18 (loaded via CDN)
- **Styling**: Custom CSS (embedded)
- **Components**:
  - `App` - Main container
  - `Sidebar` - Navigation tabs
  - `Topbar` - Page titles
  - `UploadTab` - Image upload + 3 views
  - `ChatTab` - Chat interface
  - `ReportTab` - RAG report display
  - `CellsTab` - Cell explorer
  - `History` - Analysis history

### Backend (Flask)
- **File**: `app/flask_app.py`
- **Endpoints**:
  - `POST /api/upload` - Upload & analyze
  - `GET /api/analyses` - List all analyses
  - `GET /api/analysis/<id>` - Get specific analysis
  - `GET /api/cells/<id>` - Get cells for analysis
  - `GET /api/analysis-report/<id>` - Generate RAG report
  - `POST /api/chat` - Send chat message
  - `GET /api/chat/<id>` - Get chat history
  - `GET /api/image/<path>` - Serve images

### Data Storage
- **Analyses**: In-memory Python dict `analyses`
- **Chat history**: In-memory Python dict `chat_history`
- **Images**: File system in `data/outputs/`
- **Uploads**: File system in `data/uploads/`
